# 03 · 精读方法论（如何把一个论文仓变成自己的东西）

> 本库 27 仓精读用的方法。新仓入库、或你读到任何新论文代码，都按这套流程过一遍。

## 第一步：档案卡（README 级，30 分钟）

读 README 全文 + 顶层结构 + 1-2 个关键脚本开头，回答：

1. 它解决什么问题（一句话功能）？→ 归入 P0–P8 分类
2. License 是什么？**无 LICENSE = 仅可学习、不可转载**
3. 运行入口在哪（notebook/R/CLI）？env 文件有没有？
4. 复现难度（低/中/高）：数据在不在仓内？依赖老不老？路径硬编码吗？

产出：`01_资料库/档案卡/<owner>__<repo>.md`（模板见 `_模板.md`）。

## 第二步：精读（S 级仓才做，半天）

### 代码结构走读
目录→模块职责→入口链怎么串。用 grep/head/wc 高效定位；主承载文件读全文；数据文件不读。

### 技术路线还原
从固定清单勾选该仓实际执行的步骤（顺序忠实）：
`[数据读取, 质控QC, 归一化, HVG, 降维, 聚类, 注释, 去卷积, 空间邻域/域, 细胞通讯, 亚细胞, 空间统计, 配准/3D, 多样本整合, 绘图, 导出]`
——这是全库共性骨架统计的原料（见[分类分析报告 §3](01_资料库/分类分析报告_一期.md)）。

### 工程审计（7 维 × 0–2 分，必须 文件:行号 证据）

| 维度 | 0 分典型 | 2 分典型 |
|---|---|---|
| ①职责单一/模块化 | 万能脚本、四份复制 | hover_net 工厂式加载 |
| ②命名规范 | `susbet` 拼写错误 | spatialecotyper API 命名 |
| ③安全性 | `/mnt/sata1` 硬编码 | 配置-代码分离（sharp） |
| ④最简化 | 死代码、新旧版本打架 | snp2cell |
| ⑤逻辑健壮性 | 裸 except、import 即实例化 | 权重 strict 校验（hover_net） |
| ⑥可复现性 | 无 seed、requirements 漂移 | seed 三表+锁文件（snp2cell） |
| ⑦验证纪律 | 论文附件从未运行过 | CI 回归测试（snp2cell） |

### 模式提取（PATTERN 卡）
只登记**真正值得搬运**的做法，写清：来源（文件:行号）、场景、最小代码骨架、搬运条件（依赖/许可/改造点）。宁缺毋滥。

## 第三步：清创红线（借鉴前必查）

1. 硬编码路径 → 换配置
2. 无 seed → 补 `set_all_seeds`
3. import 副作用 → 改延迟加载
4. 依赖冲突 → 先跑通再谈借鉴
5. License 限制 → 决定"抄思路"还是"搬代码"

## 产出归档

```
01_资料库/精读笔记/<owner>__<repo>.md   （走读+路线+审计+总评）
02_工作流开发/范式登记册/PATTERN-0XX_<短名>.md
01_资料库/精读汇总.csv                  （步骤序列+总分，登记册索引同步更新）
```
