**共性框架（≥24/27）＝ 候选主流程**：`读取 → QC → 归一化(+HVG) → 降维 → 聚类 → 注释 → 绘图/导出`。这条流程与官方线、OV 线的结构完全一致。三条线在这里汇合，把它定为正式主流程的证据充分。

### 3.2 分叉点（因场景或平台不同而分化的步骤）

- **装载层分三条**：Xenium outs 直读（spatialdata/ov.io）｜ISS 图像流程（ASHLAR→解码→分割，Moldia 三件套）｜官方结果复用（大样本）。
- **注释两条路线**：百万细胞级用 scVI 接 scANVI 做半监督（crc-atlas）；少样本用 scVI+celltypist 预训练模型直测，再加子集精修（crohns 三段式）。A2 模块建议以少样本直测这条路线为主流程，百万细胞路线用于大规模分支。
- **niche/生态型的输出约定已定型**：通用格式是 `adata.obs 标签列 + 邻接矩阵`；CellCharter 系（delaunay→aggregate→AutoK）与 NMF 系（SpatialEcoTyper）两套方法并立，候选不止一个（与我们的多候选固定做法天然契合）。
- **配准三种做法**：官方 Explorer 人工配准+矩阵导出（janesick）、BigWarp/napari 3D 配准（mushroom）、HPC 管线托管（estorrs）。人工环节目前没有代码替代方案，是整条流程里明确的一处断档。

### 3.3 共同缺失（= 可改进处，二期重点）

1. **A4 细胞通讯在 72 仓中没有专门仓库**（只有 SPACE 沾边，另有一些应用仓调用 CellChat）。生态工具（CellChat/LIANA+）能补上通用分析，但空间特异的通讯验证方法仍然缺失。
2. **注释的人工环节在 5 个应用仓中有 4 个无法纯代码复现**（TRM、UCSF、tnbc、Kidney 都断档）。这需要一套明确的"注释计划加验证记录"协议（我们的注释列约定正好补上这个空缺）。
3. **QC 指标不统一**：各仓自定义阈值/指标（唯一专门做 QC 的仓 SpatialQM 提供了可照搬的指标定义层）。
4. **错误处理普遍缺失或悄悄吞掉报错**；流程串接脚本里复制粘贴 bug 高发（基准组 5 仓中 4 仓实读出真 bug）。
5. **无 seed / 无 CI 测试**：27 仓中仅 snp2cell 有像样回归测试、SpatialQM 有 CI（33 行）。

**均值 8.3/14（59%）**。与既有认知一致，两种极端并存：一种是**方法可信、软件不可用**（手稿附带代码的仓常见），另一种是**配套管理成熟、核心代码粗糙**（TRM 用 pixi 管环境很规范，代码主体里却到处是不写错误类型的 except）。

### 4.2 共性硬伤 TOP5（照搬前必须先清理修复）

1. **硬编码作者机路径**（`/mnt/sata1`、`~/`、`/data/projects/robin/`、`/scratch`）。5 个精读批次全部报出，是 0 分维度最集中的地方。
2. **无 seed / 无版本锁**（KFold 无 seed、torch 不设 seed、requirements 与实际环境脱节）。
3. **import 副作用**（import 一执行就跑代码：ISS_postprocessing `segmentation.py:10,124` import 即实例化 Cellpose，断网环境下会卡死；Xenium_benchmarking `__init__.py` 语法非法）。
4. **开箱即坏的依赖冲突**（ImagePseudo 的 `scipy.misc` 与 `scipy==1.12.0` 冲突已实测确认；torch1.6/CUDA10.2 旧版本组合）。
5. **流程串接脚本复制粘贴 bug**（ST_Comparison 有 4 处语法/复制粘贴错误，等于一份从未运行过的论文附件；SpatialBenchmarking 路径少写一个"/"）。

### 4.3 superpowers / SOLID 式工程实践：**结论=普遍缺失，但亮点可数**

- 有：snp2cell 的 seed 三表+置换检验+CI 回归；sharp 的配置-代码-容器-校验四分离；ist_benchmarking 的幂等检查点+常量集中管理；QuKunLab 的统一 CLI 约定+注册表分派；TRM 的产数/出图双层；tnbc 的 md 手册四段式验收（图号→脚本→步骤→预期输出）+`.winner` 终版命名。
- **没有**任何一仓留下“从计划、实现到验证”三步都齐全的工作流记录（superpowers 式）；长期践行 SOLID 的仅 snp2cell/sharp 两例。
- **二期自研标准要定下来的就是这份清单**（见 §8）：文献界没有提供的工程配套管理，用我们已经验证的 zoro 固定要求和登记册里的 46 张卡补上。

## 7. 避坑清单汇总（一期新增部分，沿用 ov工作流测试既有坑位）

**环境**：torch1.6/CUDA10.2 与 torch==1.5.0 旧版本组合难复现；scipy.misc 与 scipy≥1.10 冲突；annoy/javabridge Windows 编译失败（走 WSL）；cupy/cuml Windows 不可用（WSL2）；pybiomart/pybiomart 类需联网；presto 装机可能要 GITHUB_PAT。
**克隆**：尾随空格目录名 Windows 无法 checkout（IN-DEPTH 案例，sparse-checkout 绕过）；submodule 仓需 `--recursive`（Xenium_benchmarking、mip）；Google Drive/Synapse/DUA 申请的数据不在仓内。
**代码**：import 即实例化模型（无网卡死）；同名函数冲突（SPATCH）；"MLE 推断"名不副实（janesick 实为比例归一化）；论文附件代码可能从未运行过（ST_Comparison 4 处语法错误）。
**许可**：33/72 无 LICENSE；限制性许可四例（Stanford/GRL/CC BY-NC/UTSW）。引用与照搬前逐仓核对档案卡。
**数据**：`glob('output*')` 就地读目录（apoe 仓）；RData 散放 744MB；`rm(list=ls())`+相对路径（LungPCA）。
